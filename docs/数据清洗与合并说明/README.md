# 看板数据如何清洗、筛选与合并

这份文档供查看网站代码和数据口径的同事阅读。它只解释当前程序的实际行为，**不参与运行**，也不是一份需要上传或执行的配置文件。真正决定采集网址、清洗规则和处理步骤的文件见文末“代码位置”。

## 一、数据从哪里来，到哪里去

```text
Windows 下载程序导出卖家精灵 Excel
        ↓ 上传
data/source/YYYY-MM-DD/ 原始 Excel（原样保留）
        ↓ GitHub Actions 自动触发
识别文件与来源 → 按站点/品类/日期分组 → 筛选商品 → 按 ASIN 合并去重
        ↓
data/merged/YYYY-MM-DD/ 合并后的 Excel
data/processed/dashboard-data.json / dashboard-data.json.gz 看板数据
data/processed/cleaning-audit.json 排除、待复核与重复记录
        ↓
网站前端只读取 GitHub 中的 dashboard-data.json.gz 并展示
```

上传原始 Excel 后，`.github/workflows/build-dashboard-data.yml` 先运行测试，再执行清洗程序、压缩 JSON，最后把结果提交回仓库。如果某份 Excel 无法读取，程序返回错误，流程不会把不完整的 JSON 覆盖到已有看板数据上。原始文件保留在 `data/source/`，方便日后核对和重新处理。

目前配置有 **7 个站点、5 个品类、35 个站点品类组、37 个下载来源**。德国和法国洗地机各有两个来源，所以下载来源数大于站点品类组数。以上数量来自当前 `tasks_v2.json`，今后新增榜单时会变化。

## 二、程序怎样认出一个榜单

原始文件名包含站点、品类、亚马逊榜单节点编号和采集日期，例如：

```text
BSR_FR_Wet-Dry-Floor-Washer_Node1854941031_Top50_2026-10-20.xlsx
```

程序用文件名和 `tasks_v2.json` 找到对应采集任务；旧版没有 `_Node…` 的文件仍可读取。它从商品工作表读取有 ASIN 的行，将 ASIN 统一为大写，并把卖家精灵的“月销量”“月销售额(币种)”等列转成看板字段。没有 ASIN 的行不算商品。原 Excel 的 `Brands`、`Sellers` 统计表不直接作为清洗后的汇总依据，因为其中可能包含被排除的商品。

**分组键是“站点 + 品类 + 日期”。**只有三个值都相同的来源才会合并。不同站点的同一 ASIN、不同日期的榜单不会混在一起；某天缺少一个来源，也不会自动借用前一天的文件。

## 三、每件商品怎样被筛选

规则写在 `cleaning/cleaning_rules.json`，按三层组合：

1. `default`：所有站点与品类共享，例如明确的替换件、清洁液和工业设备标题。
2. `categories`：某个品类共享，例如洗地机排除部分桶式吸尘器、车库吸尘器、便携布艺清洗机和 Dyson V 系列 Submarine 吸尘器。
3. `groups`：特定“站点/品类”的补充规则，例如 `DE/Wet-Dry-Floor-Washer` 和 `FR/Wet-Dry-Floor-Washer`。

排除标题规则逐层累加；站点品类的“必须命中”标题规则会替换品类层的同类规则。代码对一件商品按以下**固定优先级**判断：

| 顺序 | 条件 | 处理 |
| --- | --- | --- |
| 1 | ASIN 在 `keep_asins` | 明确保留，即使标题命中排除规则。 |
| 2 | ASIN 在 `exclude_asins` | 明确排除。 |
| 3 | 标题为空 | 标记待复核，不进入看板大盘。 |
| 4 | 标题命中任一 `exclude_title_patterns` | 排除，并记录命中的规则。 |
| 5 | 该组设置了 `require_title_patterns`，但标题一个也没命中 | 标记待复核，不进入已确认大盘。 |
| 6 | 以上都没有发生 | 保留。 |

标题规则是**不区分大小写的 Python 正则表达式**，运行时由代码判断；这里没有逐次调用 AI 识别商品。明确排除和待复核是两种不同结果：前者已有排除依据，后者是现有标题证据不足，留给人工核查。没有设置“必须命中”规则的其他榜单，未命中排除规则的商品会保留；因此它们不是经过完整人工认证的产品清单。

### 洗地机的特殊范围

- **德国站**：两个榜单节点 `218877962031` 与 `2077530031` 合并。要求标题体现家用吸拖洗一体机或已确认型号；排除工业、商用桶式、吸灰机、机器人、地毯清洗机及耗材。追觅等只出现在第二个来源的商品仍可进入合并榜单。
- **法国站**：两个榜单节点 `218877814031` 与 `1854941031` 合并。要求标题体现家用洗地机或已确认型号；排除工业桶式、吸灰机、布艺/地毯清洗机、机器人与普通吸尘器。无法确认的产品待复核。
- **Dyson 的边界**：按现有规则，`Pencilwash` 可以作为洗地机；Dyson V 系列 `Submarine` 属于普通吸尘器加湿拖头，不计入洗地机。
- **其他站点洗地机**：共享通用品类排除规则，但目前没有德法两站这样完整的站点专属“必须命中”规则。发现误入商品时，应在对应站点品类规则中补充证据，而不是认为现有规则已覆盖所有情况。

其他品类也有针对性判断：除螨仪要求标题有床垫、除螨等证据；布艺清洗机排除没有布艺/地毯清洗证据的纯蒸汽机。通用的明显耗材和工业设备排除规则对全部站点生效。

## 四、两个来源怎样合成一个榜单

对同一组的来源，程序按 `tasks_v2.json` 中任务出现的顺序处理。商品先经过上述筛选，再以 **ASIN 去重**：

- 不同 ASIN：各保留一条，进入同一份商品列表。品牌和卖家的月销量、月销售额按这些保留商品重新汇总。
- 同一 ASIN 出现在两个榜单：只保留顺序靠前来源的整条商品数据；记录两个来源及月销量、月销售额、价格等字段的差异。**不会把相同 ASIN 的销售额相加**，否则同一 SKU 会被重复计算。
- 清洗后按商品的卖家精灵**月销售额**从高到低重新编号 `rank`；原榜单排名仍保存在 `sourceRank` 和来源记录中，原始亚马逊 BSR 字段不被改写。缺少月销售额的商品保留在末尾，不凭空估算。

看板中的品牌份额目前采用**清洗后商品的月销量占比**，品牌列表按月销售额排序。原始商品表没有可靠的逐 SKU 年销量/年销售额，因此重算的品牌、卖家年度汇总留空。前端的 Top10、Top20、Top50 只限制显示数量，品牌等大盘统计使用该组全部已清洗且去重的商品。

例如 2026-10-20 的法国两份实测文件共有 53 条原始商品行；当前规则留下 11 条家用洗地机，排除 40 条，另有 2 条待复核。这是**该日期的处理结果**，不是以后每次都固定的数量。

## 五、输出文件各有什么作用

| 位置 | 内容与用途 |
| --- | --- |
| `data/source/YYYY-MM-DD/` | 原始导出文件，供追溯和重新清洗；看板不直接读取。 |
| `data/merged/YYYY-MM-DD/MERGED_站点_品类_日期.xlsx` | 清洗和去重后的商品表，沿用原 Excel 列结构、商品链接和图片，并重算 `Brands`、`Sellers` 工作表。若两个来源的列结构不一致，程序报错，不静默丢列。 |
| `data/processed/dashboard-data.json` | 全部日期、站点和品类的结构化看板数据，含商品、品牌、卖家、来源覆盖等信息。 |
| `data/processed/dashboard-data.json.gz` | 上一文件的压缩版；当前网站前端从 GitHub 读取它。 |
| `data/processed/cleaning-audit.json` | `excluded`、`review`、`duplicate` 事件，包含 ASIN、标题、原因、来源文件/网址及原始排名，供检查规则。 |

若某个日期缺少已配置来源，数据集会给出 `missingSourceNodes`，并把 `sourceCoverageComplete` 设为 `false`。这表示该日期的来源覆盖不完整；有商品数据不等于两个榜单都已经下载。看板“数据覆盖”页会显示缺少来源的信息。

## 六、目前口径的边界和维护方式

这套规则依据**商品标题、已确认 ASIN、来源榜单和卖家精灵导出的指标**自动执行。标题可能缺词、翻译变化或被商家误写，因此任何关键词规则都可能误排或漏排。待复核商品不会计入已确认竞品大盘，确认后可以在相应的站点品类规则中增加例外 ASIN 或更准确的标题模式，并用测试和审计记录验证。不要只凭品牌名称一概纳入或排除：同一品牌也可能销售耗材、工业设备或其他品类。

看板展示的是**已采集榜单覆盖的竞品样本**，不是亚马逊完整市场。某日期的 35 个站点品类组未全部上传时，跨站点比较要先看覆盖情况；历史日期若缺少后来新增的榜单，不能把这种来源差异当作真实市场涨跌。

代码位置：`tasks_v2.json` 定义下载来源和先后顺序；`cleaning/cleaning_rules.json` 定义筛选规则；`cleaning/build_dashboard_data.py` 负责读取、判断、去重、汇总与生成 JSON；`cleaning/merged_excel.py` 生成合并 Excel；`.github/workflows/build-dashboard-data.yml` 负责自动运行和提交结果。**修改本文档本身不会修改清洗结果，也不会触发下载、清洗或 EXE 构建。**
